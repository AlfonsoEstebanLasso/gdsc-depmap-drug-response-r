# Errata of the 2019 code

The scripts in `legacy/` are published exactly as deposited with the thesis
(June 2019). Reading them again in 2026 revealed the eight methodological
defects below. They are **not corrected in v0.1**; the planned v1.0 will be a
corrected reimplementation. Line numbers refer to the files in `legacy/`
(the deposited originals are the same lines minus 10, the provenance header).
Every defect was verified in the code before being listed.

| # | Defect | Files and lines | What the code does | Effect on the thesis results | Planned fix (v1.0) |
|---|---|---|---|---|---|
| 1 | R-squared computed as the squared correlation between the observed value and the residual | `h2ocontinuosRF.R` 127-128, 218-219; `randomsearchcontinuosRF.R` 78-79, 124-125; `ridgelassoelasticcontinuosrandomsearch.R` 72-73, 99, 122, 186-187, 221, 254; `SVMLinealcontinuos.R` 83-84 (line 136 uses `miscTools::rSquared`, which is correct) | Defines `rsq <- function(x, y) cor(x, y)^2` and calls it as `rsq(y, y - prediction)`. That is cor(y, residual)^2, not the coefficient of determination; it approaches 1 whenever the prediction is nearly constant, because then the residual is almost y itself | The R-squared values reported for the regression models are not coefficients of determination, and the R-squared equal to 1 highlighted in the thesis for the most penalized models is an artefact of this calculation, not a perfect fit | Compute R-squared as 1 - SSres/SStot on the test set (or use `caret::R2`), together with RMSE and MAE |
| 2 | `randomForest()` receives arguments that do not exist in that package and are silently ignored | `h2ocontinuosRF.R` 110-117, 202-209; `h2odiscretizadosRF.R` 121-128, 206-213 | After tuning `max_depth`, `min_rows`, `nbins` and `sample_rate` in h2o, the final model is refitted with `randomForest::randomForest()` passing those names; `randomForest` only understands `ntree`, `mtry`, `nodesize`, `maxnodes` and `sampsize`, so the tuned values are dropped | The final random forests are default `randomForest` models with the tuned `ntree` and `mtry` only; the hyperparameter search described in the thesis is not reflected in the reported fits | Fit the final model with `h2o.randomForest()` using the tuned grid, or map the parameters to their `randomForest` equivalents |
| 3 | The "Elastic Net" of the 80/20 split calls `cv.glmnet()` without `alpha` | `ridgelassoelasticcontinuosrandomsearch.R` 112-115; `ridgelassoelasticdiscretizadosrandomsearch.R` 118-122 | `cv.glmnet()` defaults to `alpha = 1`, so the model labelled Elastic Net is a second lasso fit (the 60/20/20 split tunes `alpha` with caret and is a true elastic net) | The 80/20 elastic net results in the thesis duplicate the lasso results instead of describing an elastic net | Tune `alpha` over a grid for both splits |
| 4 | `caret::train()` with `tuneLength` but without `search = "random"` performs a grid search, not the random search described | `randomsearchcontinuosRF.R` 59-67, 114; `randomsearchdiscretizadosRF.R` 70-78, 119; `ridgelassoelasticcontinuosrandomsearch.R` 160, 239; `ridgelassoelasticdiscretizadosrandomsearch.R` 159, 228 | `trainControl()` is created without `search = "random"`, so `tuneLength = 20` produces a regular grid of 20 candidate values | The thesis calls these fits "random search"; they are grid searches. The results stand, but the method is mislabelled | Use `trainControl(search = "random")` or describe the procedure as grid search |
| 5 | The class label assigns "Sensible" (sensitive) to AUC values at or above the third quartile | `h2odiscretizadosRF.R` 54-57; `randomsearchdiscretizadosRF.R` 52-55; `ridgelassoelasticdiscretizadosrandomsearch.R` 52-55; `SVMLinealdiscretizados.R` 53-56 | `class[class >= Q3] <- 1`, then level 1 is labelled "Sensible" and level 0 "Resistente" | In GDSC a higher AUC of the dose-response curve means less drug effect (more resistant), so the labels are probably inverted: the minority class called sensitive is the most resistant quartile. Accuracies are unaffected, but the biological reading of the confusion matrices and ROC curves is reversed | Define sensitivity as low AUC (for example below the first quartile) and document the rule |
| 6 | The 200 most variable genes and the class threshold are chosen on the whole dataset before the train/test split (information leakage) | Gene selection: `h2ocontinuosRF.R` 27-28, `h2odiscretizadosRF.R` 28-29, `SVMLinealcontinuos.R` 27-28 and the same block in the other model scripts; threshold: `h2odiscretizadosRF.R` 54, `randomsearchdiscretizadosRF.R` 52, `ridgelassoelasticdiscretizadosrandomsearch.R` 52, `SVMLinealdiscretizados.R` 53; partitions created later, for example `h2ocontinuosRF.R` 142 and 148 | `colVars()` over all cell lines selects the genes, and `Quantile(..., 0.75)` over all cell lines sets the class cut-off, before `sample()` splits the data | Test-set performance is optimistically biased: the variance filter (unsupervised, small effect) and the quartile threshold (uses the response, larger effect for classification) see the test cell lines | Select genes and compute the threshold inside each training fold |
| 7 | `SVMLinealcontinuos.R` uses 2000 genes instead of the 200 of the thesis and saves the wrong object; `ridgelassoelasticdiscretizadosrandomsearch.R` has misplaced parentheses in three `predict()` calls | `SVMLinealcontinuos.R` 27 (`n <- 2000`) and 146 (`save(svmfit.opt, ...)` for the 60/20/20 model, which is `svmfit.opt602020`, line 124); `ridgelassoelasticdiscretizadosrandomsearch.R` 186, 216, 245 | The SVM regression is trained on 2000 genes while all other scripts use 200, and the saved 60/20/20 SVM model is the 80/20 model. In the three `predict()` calls, `type = "response"` and the lambda choice are passed to `as.matrix()` instead of `predict()`, so `predict()` uses its defaults (link scale, all lambdas) | The SVM regression results are not comparable with the other models (different feature set); the saved SVM object for the 60/20/20 split is wrong; the ROC curves of the penalized logistic models on the 60/20/20 split are built from the default `predict()` output rather than from the intended response probabilities at the chosen lambda | Use the same 200-gene matrix everywhere, save the right object, and close the `as.matrix()` call before `type` and `s` |
| 8 | Random partitions are not reproducible in R 3.6 or later without `RNGkind(sample.kind = "Rounding")` | `set.seed()` followed by `sample()` in every model script, for example `h2ocontinuosRF.R` 50, 142, 148; `randomsearchcontinuosRF.R` 50, 62, 94, 100, 109; `ridgelassoelasticcontinuosrandomsearch.R` 48, 60, 136, 143, 166, 234 | The scripts rely on `set.seed(1234)`, `set.seed(1)` and `set.seed(123)` with `sample()`. R 3.6.0 changed the default `sample()` algorithm (sample.kind = "Rejection") | Re-running the scripts with a current R gives different train/test partitions and therefore different numbers from the thesis, even with the same seeds | Call `RNGkind(sample.kind = "Rounding")` to reproduce 2019, or fix the partitions explicitly with stored indices |

Additional observations, not counted among the eight defects: hyperparameters
are copied by hand from the console into the final fits (so each script is
tied to one drug), the output file names always contain the name of one drug,
`creacionmatriz.R` creates an object named `rm` (line 49), and some fits
return warnings about obsolete arguments with current package versions.
