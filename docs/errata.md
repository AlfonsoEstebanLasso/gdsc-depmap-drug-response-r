# Errata of the 2019 code

The scripts in `legacy/` are published exactly as deposited with the thesis
(June 2019). Reading them again in 2026 revealed seven methodological defects
and one reproducibility caveat, listed below as eight items. They are **not
corrected in v0.1.0**; the planned v1.0 will be a corrected reimplementation.
Line numbers refer to the files in `legacy/` (the deposited originals are the
same lines minus 10, the provenance header). Every item was verified in the
code before being listed, and the table was checked a second time by an
independent review.

| # | Defect | Files and lines | What the code does | Effect on the thesis results | Planned fix (v1.0) |
|---|---|---|---|---|---|
| 1 | R-squared computed as the squared correlation between the observed value and the residual | `h2ocontinuosRF.R` 127-128, 218-219; `randomsearchcontinuosRF.R` 78-79, 124-125; `ridgelassoelasticcontinuosrandomsearch.R` 72-73, 99, 122, 186-187, 221, 254; `SVMLinealcontinuos.R` 83-84 (line 136 uses `miscTools::rSquared`, which is correct) | Defines `rsq <- function(x, y) cor(x, y)^2` and calls it as `rsq(y, y - prediction)`. That is cor(y, residual)^2, not the coefficient of determination; it approaches 1 whenever the prediction is nearly constant, because then the residual is almost y itself | The R-squared values reported for the regression models are not coefficients of determination, and the R-squared equal to 1 highlighted in the thesis for the most penalized models is an artefact of this calculation, not a perfect fit | Compute R-squared as 1 - SSres/SStot on the test set (or use `caret::R2`), together with RMSE and MAE |
| 2 | `randomForest()` receives arguments that it does not accept, and they are silently ignored | `h2ocontinuosRF.R` 110-117, 202-209; `h2odiscretizadosRF.R` 121-128, 206-213 | After tuning `max_depth`, `min_rows`, `nbins` and `sample_rate` in h2o, the final model is refitted with `randomForest::randomForest()` passing `max_depth`, `min_row`, `nbin` and `sample_rate` (two of the names do not even match the h2o names, and `nbin = 35` is outside the explored grid). `randomForest` has no such arguments: they fall into `...` and are dropped without a warning. The approximate equivalents would be `nodesize` (for `min_rows`), `maxnodes` (for the depth) and `sampsize` (for `sample_rate`); `nbins` has none | The final random forests are default `randomForest` models with the tuned `ntree` and `mtry` only; the hyperparameter search described in the thesis is not reflected in the reported fits | Fit the final model with `h2o.randomForest()` using the tuned grid, or map the parameters to their `randomForest` equivalents |
| 3 | The "Elastic Net" of the 80/20 split calls `cv.glmnet()` without `alpha` | `ridgelassoelasticcontinuosrandomsearch.R` 112-115; `ridgelassoelasticdiscretizadosrandomsearch.R` 118-122 | `cv.glmnet()` inherits `alpha = 1` from `glmnet()`, so the model labelled Elastic Net is a second lasso fit, with different cross-validation folds because no seed is set before it (the 60/20/20 split tunes `alpha` with caret and is a true elastic net) | The 80/20 elastic net results in the thesis are those of a second lasso, close to but not identical to the first one, instead of an elastic net. The regression scripts also select `lambda.1se` while the classification scripts select `lambda.min`, an inconsistency the thesis does not discuss | Tune `alpha` over a grid for both splits and use the same lambda rule everywhere |
| 4 | `caret::train()` with `tuneLength` but without `search = "random"` performs a grid search, not the random search described | `randomsearchcontinuosRF.R` 59-67, 114; `randomsearchdiscretizadosRF.R` 70-78, 119; `ridgelassoelasticcontinuosrandomsearch.R` 160, 239; `ridgelassoelasticdiscretizadosrandomsearch.R` 159, 228 | `trainControl()` is created without `search = "random"`, so `tuneLength = 20` produces a regular grid: for `method = "rf"` the 19 distinct `mtry` values of `caret::var_seq(200, 20)`, and for `method = "glmnet"` `alpha = seq(0.1, 1, length = 20)` crossed with up to 20 lambdas. The alphas finally used, 0.8105263 and 0.1473684, are elements 16 and 2 of that sequence, which confirms the grid. The two `train()` calls without `trControl` (lines 114 and 119) fall back to the default bootstrap resampling instead of repeated cross-validation | The thesis calls these fits "random search"; they are grid searches, and two of them use bootstrap rather than cross-validation. The results stand, but the method is mislabelled | Use `trainControl(search = "random")` or describe the procedure as grid search; pass the same `trControl` to every call |
| 5 | The class label assigns "Sensible" (sensitive) to AUC values at or above the third quartile | `h2odiscretizadosRF.R` 54-57; `randomsearchdiscretizadosRF.R` 52-55; `ridgelassoelasticdiscretizadosrandomsearch.R` 52-55; `SVMLinealdiscretizados.R` 53-56 | `class[class >= Q3] <- 1`, then level 1 is labelled "Sensible" and level 0 "Resistente" | In GDSC a higher AUC of the dose-response curve means less drug effect (more resistant), so the labels are probably inverted: the minority class called sensitive is the most resistant quartile. Accuracies are unaffected, but the biological reading of the confusion matrices and ROC curves is reversed | Define sensitivity as low AUC (for example below the first quartile) and document the rule |
| 6 | The 200 most variable genes and the class threshold are chosen on the whole dataset before the train/test split (information leakage) | Gene selection: `h2ocontinuosRF.R` 27-28, `h2odiscretizadosRF.R` 28-29, `SVMLinealcontinuos.R` 27-28 and the same block in the other model scripts; threshold: `h2odiscretizadosRF.R` 54, `randomsearchdiscretizadosRF.R` 52, `ridgelassoelasticdiscretizadosrandomsearch.R` 52, `SVMLinealdiscretizados.R` 53; partitions created later, for example `h2ocontinuosRF.R` 51 (`sample.split`), 142 and 148 (`sample`) | `colVars()` over all cell lines selects the genes, and `Quantile(..., 0.75)` over all cell lines sets the class cut-off, before the data are split | Both steps see the test cell lines, so the test-set estimates are not strictly out of sample. The magnitude of the effect is expected to be small (an unsupervised variance filter and a single scalar threshold) and has not been quantified; it will be measured in v1.0 by comparing global selection with selection inside each fold | Select genes and compute the threshold inside each training fold |
| 7 | `SVMLinealcontinuos.R` uses 2000 genes instead of the 200 of the thesis and saves the wrong object; `ridgelassoelasticdiscretizadosrandomsearch.R` has misplaced parentheses in three `predict()` calls | `SVMLinealcontinuos.R` 27 (`n <- 2000`) and 146 (`save(svmfit.opt, ...)` for the 60/20/20 model, which is `svmfit.opt602020`, line 124); `ridgelassoelasticdiscretizadosrandomsearch.R` 186, 216, 245 (and 182-183, 212-213, 241-242) | The SVM regression is trained on 2000 genes while all other scripts use 200, and the saved 60/20/20 SVM model is the 80/20 model. In the three `predict()` calls, `type = "response"` and the lambda choice are passed to `as.matrix()` instead of `predict()`, so `predict()` returns the linear predictor; nearby, `s = "lambda.min"` is passed to `glmnet` objects fitted with a single lambda, where it has no meaning | The SVM regression results are not comparable with the other models (different feature set) and the saved SVM object for the 60/20/20 split is wrong. The misplaced parentheses have no effect on the ROC curves or AUC values: the linear predictor is a monotone transformation of the probability, each of those fits has a single lambda, and ROCR only uses the ranking of the scores | Use the same 200-gene matrix everywhere, save the right object, and close the `as.matrix()` call before `type` and `s` |
| 8 | Reproducibility caveat: the random partitions and resampling of 2019 are not reproduced by a current R, even with the same seeds | `sample.split()` for the 80/20 split: `h2ocontinuosRF.R` 51, `h2odiscretizadosRF.R` 62, `randomsearchcontinuosRF.R` 51, `randomsearchdiscretizadosRF.R` 60, `ridgelassoelasticcontinuosrandomsearch.R` 49, `ridgelassoelasticdiscretizadosrandomsearch.R` 62, `SVMLinealcontinuos.R` 52, `SVMLinealdiscretizados.R` 61; `sample()` for the 60/20/20 split: `h2ocontinuosRF.R` 142, 148, `randomsearchcontinuosRF.R` 94, 100, `ridgelassoelasticcontinuosrandomsearch.R` 136, 143 and equivalents; `createDataPartition()`: `ridgelassoelasticdiscretizadosrandomsearch.R` 141; `h2o.grid()` without `seed`: `h2ocontinuosRF.R` 81-87, 173-179, `h2odiscretizadosRF.R` 92-98, 177-183 | The 80/20 split uses `caTools::sample.split()`, which relies on `runif()` and is not affected by the R 3.6.0 change of the default `sample()` algorithm. The 60/20/20 split uses `sample()`, as do `createDataPartition()` and the internal folds of `cv.glmnet`, caret and `tune`: these depend on `sample.kind` and, because the `sample()` calls are not immediately preceded by `set.seed()`, on the random numbers consumed by the fits run before them. The h2o searches use the `RandomDiscrete` strategy with `max_runtime_secs` and no `seed`, so the set of models explored depends on the clock and on the Java generator | Re-running the scripts gives the same 80/20 partitions but different 60/20/20 partitions, different internal folds and different h2o grids, so the numbers of the thesis cannot be reproduced exactly | `RNGkind(sample.kind = "Rounding")` is necessary but not sufficient to approach the 2019 partitions; v1.0 will store the partition indices, set `seed` in `h2o.grid()` without a time budget, and record package versions with renv |

## Additional observations

Found during the 2026 review and not counted among the eight items above
because they go beyond the scope of this errata. They are listed so that the
v1.0 reimplementation can address them.

- `h2odiscretizadosRF.R` 113-118 and 198-203: `h2o.getGrid(..., sort_by = "Accuracy", decreasing = FALSE)` prints the grid from the worst to the best model, whereas the regression script sorts by RMSE ascending, which is correct; the hyperparameters copied by hand at 121-128 and 206-213 may come from the wrong end of the table. `stopping_metric = "mse"` (94, 179) does not match the selection metric.
- `SVMLinealdiscretizados.R` 101-109 and 158-166: the ROC curve is built from `decision.values`, whose sign follows the order of the classes in the training data (libsvm), not the factor levels that ROCR uses as positive class; the SVM ROC curves may therefore be inverted (an issue the second edition of the ISLR lab fixed by negating the decision values).
- In seven of the eight model scripts the `train60` subset is created but never used (for example `h2ocontinuosRF.R` 149, 153): hyperparameters are tuned on `validation20`, the final model is fitted on `remain80` and tested on `testing20`, so the "60/20/20" scheme is really "tune on 20, fit on 80, test on 20".
- `ridgelassoelasticdiscretizadosrandomsearch.R` 162-178: the 60/20/20 ridge logistic model is fitted with `lambda = 1000`, the upper end of the grid `10^seq(-3, 3, length = 100)`, selected by accuracy in a 75/25 problem; such a model is nearly constant and predicts the majority class for almost every cell line.
- `randomsearchdiscretizadosRF.R` 84: the final `mtry = 43` does not belong to the grid generated by `tuneLength = 20` (`caret::var_seq(200, 20)`), so it cannot be traced to the search in the deposited script.
- `SVMLinealdiscretizados.R` 88, 144, 96, 106, 153, 163 and `SVMLinealcontinuos.R`: `svm()` and `predict.svm()` receive arguments they do not have (`family`, `type`, `decision.values` in the fit), which are ignored, as in item 2.
- `h2ocontinuosRF.R` 65, 157 and `h2odiscretizadosRF.R` 76, 161: both searches of each script reuse the same `grid_id` in the same h2o session, which may append the second search to the first grid.
- Hyperparameters are copied by hand from the console into the final fits (so each script is tied to one drug), output file names always contain the name of one drug, `creacionmatriz.R` creates an object named `rm` (line 49), and some fits return warnings about obsolete arguments with current package versions.
